What TEA does for you

  • 🔎

    Finds what's broken

    Opens your running app in a real browser (read-only) and reports crashes, broken links, failing API calls, slow pages and missing images.

  • 🔌

    Checks the wiring

    Matches every call your frontend makes to a route your backend serves, across a separate frontend and backend, in any language.

  • 📋

    Tests every feature

    Lists every feature in your code and in the docs your AI agent wrote (CLAUDE.md, AGENTS.md, TODO), tests each one, and flags what the docs claim but was never built.

  • 🧪

    Sandbox tests

    On a copy running on your computer, TEA submits every form with test data, tries bad input, and checks private APIs refuse strangers. Off until you turn it on.

  • 🧠

    Detects your stack

    Point it at a folder. It finds the apps in it, their frameworks and languages, and where they run. No config.

  • 🧩

    Your own rules, no code

    "No console.log in the code", "Has a privacy page", "No test keys": add with one click or in three steps.

  • 🚦

    A quality gate

    Passed or Failed after every analysis, with Relaxed, Balanced and Strict presets. Blocks a bad deploy in CI.

  • ✍️

    Fix prompts

    Every issue comes with steps to see it and a prompt to paste into Cursor, Claude, Lovable or Bolt. Fix, run again, ship.

How it works

  1. 1

    Add your app

    Add project → Choose folder and detect. TEA shows what it found and suggests the local URL to test.

  2. 2

    Run an analysis

    Watch it brew live. Get the quality gate, the TEA Score, the issue counts and a full report to share.

  3. 3

    Fix the issues

    Filter by severity or area, copy the fix prompt into your AI coding tool, and run again to prove it's fixed.

  4. 4

    Make it yours

    Pick a preset, switch checks on or off, add rules of your own, and set the gate. It's all saved in one file you can commit.

One file holds every setting

You never have to touch it: every setting has a page in the Workbench. But it's all in one readable file, tea.config.yaml, that you can commit with your code or copy to another computer.

# Your app: its folders and where it runs
projects:
  - key: shop
    name: My shop
    url: http://localhost:3000
    sources:
      - { name: web, path: ../shop-web }   # role: auto
      - { name: api, path: ../shop-api }

# Change any built-in check
rules:
  crawl.slow: { params: { thresholdMs: 2000 } }

# Your own rules, no code
customRules:
  - { id: no-console, title: No console.log,
      type: forbid-text, text: "console.log(" }
  - { id: privacy, title: Has a privacy page,
      type: require-route, path: /privacy }

# Fail when ANY condition is met
gate:
  conditions:
    - { metric: critical, op: gt, value: 0 }
    - { metric: score, op: lt, value: 60 }
projects
Each app: a name, its code folders (frontend, backend or fullstack, or auto), and an optional URL to test it live.
rules
Turn any built-in check off, change how serious it is, or tune it (like what counts as a slow page). Only what you change is written.
customRules
Four kinds, no code: the code must not contain some text, must contain some text, a file must exist, a page must exist.
gate
Conditions on the score, issue counts or an area's score. Every analysis is marked Passed or Failed; in CI, a failed gate fails the build.

Get started

You need Node.js 20.9+ and git. One command installs, builds and opens the TEA Workbench in your browser.

git clone https://github.com/deepbratt/TEA.git
cd TEA
npm start

Everything runs on your own computer. TEA never installs your app's packages, never writes to your live app, and masks secrets everywhere.
